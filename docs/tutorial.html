Module 1: Why Do We Need an Agent Bill of Materials (AgBOM)?

Foundations

When an AI agent connects to external tools using MCP (Model Context Protocol), the remote tool server sends a JSON catalog (tools/list) containing tool names, free-text descriptions, and parameter schemas. Crucially, those descriptions are injected straight into the LLM's prompt context. If a remote MCP server quietly edits a description tomorrow, your agent's behavior can be hijacked without a single commit to your codebase.

Module 2: RFC 8785 JCS Canonicalization, Two-Level Hashing & Static Linting

Live Browser Lab

How do you fingerprint an MCP tool without constant false alarms—yet catch every single malicious trick? internal/canon solves this with RFC 8785 JCS (JSON Canonicalization Scheme):

  • Strip volatile transport envelopes (JSON-RPC id, nextCursor, cache TTLs) — they legitimately change every call.
  • Sort object keys recursively by UTF-16 code units & remove insignificant spacing outside strings — so shuffled JSON keys produce the exact same hash.
  • Hash RAW JSON (no Go struct round-trip!) & preserve exact string bytes — so adding 1 trailing space, invisible Unicode, or a smuggled _meta key always flips the SHA-256 hash.

Module 3: CycloneDX 1.6 AgBOM, Ed25519 DSSE & A2A Card JWS

            Cryptographic Trust Boundary
          

          

            An unsigned agbom.json inside a workspace is easy to defeat: a compromised coding agent with file write permissions could simply edit agbom.json to whitelist a malicious tool.
            That's why agbom-gate wraps the CycloneDX 1.6 document in an Ed25519 DSSE (Dead Simple Signing Envelope) using Pre-Authentication Encoding (PAE):
          

          
PAE = "DSSEv1 " + len(payloadType) + " " + payloadType + " " + len(payload) + " " + payload
sig = Ed25519.Sign(offline_private_key, PAE)

          

            At boot, agbom-gate proxy checks TWO things with a pinned read-only public key (agbom.pub): (1) byte-for-byte equality between agbom.json and the envelope payload, and (2) valid Ed25519 signature over PAE. If either fails, the proxy refuses to start.

What Else Lives in a Production CycloneDX 1.6 AgBOM?

          

            

              
1. Packages (library)

              
Lockfiles (go.mod, package-lock.json, requirements.txt, uv.lock) with PURLs.

            

            

              
2. Prompts (machine-learning-model)

              
Exact raw-byte SHA-256 of prompts/*.md via agbom:system_prompt_sha256.

            

            

              
3. MCP Servers (service)

              
Composite & per-tool SHA-256 pins, allowed_tools, step_up_approval_tools, no passthrough.

            

            

              
4. A2A Peer Agents (a2a/1.0)

              
Verifies /.well-known/agent.json JWS (EdDSA / ES256) over JCS bytes; fails closed if unsigned.

            

            

              
5. RAG & Memory (data)

              
Vector/memory stores from agbom-stores.json pinning access_mode (read-only).

            

            

              
6. Non-Human Identity (NHI)

              
SPIFFE principal (agbom:nhi_principal) propagated into every DFIR & OTLP trace span.

No Token Passthrough (Streamable HTTP)

            
If an AI client sends Authorization: Bearer user-jwt, HTTPQuarantineProxy always strips it, logs a warning, and authenticates upstream using mTLS (--tls-cert) or an externally brokered OBO token (--obo-token-cmd).

          

          

            
Blast-Radius Isolation (HTTPGateway)

            
In --routes mode (/mcp/{server-name}), each upstream server has its own state machine. Quarantining /mcp/weather-mcp leaves /mcp/trusted-email-mcp completely unaffected, while unknown routes fail closed (404 / -32098).

Try It Yourself Locally (5-Minute Terminal Lab)

          
# 1. Run all 39 tests with the Go race detector (works 100% offline!)
go test -race -v ./...

# 2. Generate Ed25519 keys & scan the clean mock MCP server
./bin/agbom-gate keygen --out /tmp/lab
./bin/agbom-gate scan --server-name weather-mcp --cmd ./bin/mock-rugpull-mcp --args "--mode=clean" \
  --allowed-tools "get_forecast" --sign-key /tmp/lab/agbom.key \
  --out /tmp/lab/agbom.json --sig-out /tmp/lab/agbom.dsse.sig

# 3. Watch the proxy quarantine a rug-pulled server (-32099) and log redacted DFIR JSON
printf '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}\n{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}\n' | \
  ./bin/agbom-gate proxy --agbom /tmp/lab/agbom.json --sig /tmp/lab/agbom.dsse.sig \
  --pub-key /tmp/lab/agbom.pub --server-name weather-mcp \
  --cmd ./bin/mock-rugpull-mcp --args "--mode=rugpull-immediate" --telemetry-log /tmp/lab/dfir.ndjson

# 4. Reconcile the captured telemetry against the signed AgBOM
./bin/agbom-gate reconcile --agbom /tmp/lab/agbom.json --sig /tmp/lab/agbom.dsse.sig \
  --pub-key /tmp/lab/agbom.pub --telemetry /tmp/lab/dfir.ndjson
